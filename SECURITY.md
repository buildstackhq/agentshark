# Security Policy

## Supported Versions

We only track security fixes on the latest `main` branch and the most recent published release.

## Reporting a Vulnerability

Do not open a public issue for an active vulnerability.

Preferred reporting path:

1. Use GitHub Security Advisories for a private report, if this repository is hosted on GitHub.
2. If that is not available, contact the maintainers through the repository's private maintainer channel.
3. If you cannot reach a private channel, open a public issue that says only that you found a security problem and ask for a private contact path. Do not include exploit details.

## What to Include

- A short description of the issue
- The affected version or commit
- Clear reproduction steps
- Any relevant logs or screenshots, with secrets removed

## What to Avoid

- API keys, tokens, cookies, or other secrets
- Exploit payloads in public issues
- Customer data or private session traces
